# 备份恢复与数据生命周期运行手册

本手册适用于当前单实例、文件持久化架构。它提供可重复的离线备份和隔离恢复演练，不能证明
正式生产环境已达到某个可用性或灾备 SLO，也不包含 Render 部署、多区域灾备或在线恢复。

## 数据清单与边界

备份根目录下固定覆盖 `chroma/`、`uploads/`、`knowledge_bases/`、`conversations/`、
`auth/` 和 `audit/`。分别包含向量索引、原始资料、知识库元数据、会话与回答、账号/会话摘要/
授权、审计链。环境变量、`.env`、API Key、TLS 私钥以及 `.key`/`.pem` 文件不属于备份；工具
发现疑似密钥文件会直接失败。认证备份包含不可逆密码摘要和会话摘要，仍应按敏感数据保护。

一致性备份要求先停止写请求。Compose 场景应先停止后端，再从六个命名卷挂载出的同一时间点
快照目录执行备份。运行中的逐文件复制不提供事务一致性保证。

## 创建与校验

```bash
uv run python scripts/backup_restore.py backup \
  --data-root /path/to/snapshot/data \
  --output /secure/off-host/rongrag-$(date -u +%Y%m%dT%H%M%SZ).tar.gz

uv run python scripts/backup_restore.py verify \
  --backup /secure/off-host/rongrag-20260817T000000Z.tar.gz
```

备份包包含版本化 `manifest.json`，记录数据集、文件大小和 SHA-256。成功创建后应把备份包移至
访问受控的异地存储，并记录备份包哈希、源版本 commit、操作人和时间；不要把备份提交到 Git。

## 隔离恢复演练

恢复目标必须不存在或为空目录，工具不会覆盖已有数据：

```bash
started_at=$(date +%s)
uv run python scripts/backup_restore.py restore \
  --backup /secure/off-host/rongrag-20260817T000000Z.tar.gz \
  --target /tmp/rongrag-restore-drill
finished_at=$(date +%s)
echo "RTO test seconds: $((finished_at-started_at))"
```

随后使用恢复目录作为六类数据路径启动一个隔离后端，执行就绪检查、管理员登录、知识库/文档
数量核对、已知查询、会话读取和审计链校验。禁止把恢复目录挂载到当前服务。演练记录至少包含：

- 源 commit、备份文件 SHA-256、清单文件数和备份时间；
- 最新业务记录时间与演练时间之差（测试 RPO）；
- 从恢复命令开始到隔离服务验证完成的秒数（测试 RTO）；
- 恢复前后知识库、文档、向量、成员、会话和审计事件计数；
- 验证结果、异常、处置人和回滚决定。

没有正式运行数据和托管存储前，只报告每次演练实测值，不承诺生产 RPO/RTO。

## 保留、删除与兼容性

- 建议按组织政策定义日/周/月保留期；当前项目不自动删除备份，删除须由授权人员执行并留证。
- 删除业务数据后，旧备份仍可能含有该数据；隐私删除流程必须同步标记并在保留期到期时清除备份。
- 格式版本由清单 `format_version` 标识；恢复工具只接受当前版本，跨版本恢复须先在隔离环境验证。
- 向量索引与 embedding 模型绑定。恢复后若配置模型不匹配，不得清空索引，应回退到匹配版本或
  从保留的原始资料在新隔离目录重建。

## 故障、升级与回滚

1. 冻结写入，记录请求 ID、告警时间、影响范围和当前 commit；保存日志但不得记录业务正文或密钥。
2. 校验最近备份；校验失败时升级事件等级并回退到上一份通过校验的备份。
3. 只在隔离目录恢复并完成数据计数、已知查询和审计链验证。
4. 升级前创建并校验备份，在隔离副本验证新版本的数据兼容性，再执行版本切换。
5. 若验证失败，停止候选版本，保留失败现场，使用前一 commit/不可变镜像和兼容恢复点回滚。
6. 正式环境切换、Render 操作和线上恢复必须另行批准；本手册不授权这些动作。

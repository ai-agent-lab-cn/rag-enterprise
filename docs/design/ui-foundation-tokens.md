# UI Foundation 视觉方向

Tailwind + shadcn/ui 迁移的**前置产物**：先定死 token 与组件长相，迁移时一次落地。
反过来做的话，429 处 `className` 要改两遍。

## 1. 诊断：问题不在审美，在同一语义有多个值

全部数字来自 `frontend/src/styles.css` 实测（814 个选择器、3137 条声明）：

| 维度 | 现状 |
| --- | --- |
| 硬编码色值 | **535 处，254 个唯一颜色** |
| 圆角 | **15 种**（8px×23、7px×21、10px×13、999px×12、12px×10、6px×8、9px×8、50%×7…） |
| 字号 | **26 种**（11px×57、12px×46、10px×31、9px×27、13px×27…） |
| padding / gap | **136 种** |
| 阴影 | 14 种 |

同一语义的多份取值：

| 语义 | 实际存在的值 |
| --- | --- |
| 主色 | `#5744dd`(--brand，生效) / `#5738dc` / `#5a4bd7` / `#6548e8` |
| 危险色 | `#d94848` / `#dc3030` / `#c2354a` / `var(--danger)`（未定义，失效） |
| 边框 | `#e5e9f2` / `#dfe3ed` / `#e6e9f1` / `#d9deea` / `#d8deeb` |
| 成功色 | `#269653` / `#25894d` / `#197d4a` / `#067647` / `#10b981`（**6 个**） |

这套视觉的观感其实是克制的——无渐变、无 Glow、圆角适中、颜色只用于表意，
已经符合《组件治理任务》第九章的方向。**要修的是一致性，不是审美**。因此本方向
**保持现有观感基调，只做收敛**，迁移后视觉变化应当很小。

### 两套并行的变量体系

- `--brand` / `--ink` / `--line` / `--canvas` / `--muted` / `--surface` / `--brand-soft` /
  `--brand-dark`：8 个，**在 `:root` 真正定义、真正生效**。
- `--color-*`：14 个，**从未定义**，全靠 `var(--color-x, #hex)` 的 fallback 兜底。
  其中 `--color-border` 的 fallback 有两个不同值（`#e5e9f2` 与 `#dfe3ed`）。

### 19 处声明因变量未定义而失效

`--text-muted`(9) / `--danger`(2) / `--accent`(2) / `--surface-soft`(1) / `--border`(1)
被引用但从未定义，且无 fallback，浏览器直接丢弃整条属性。集中在评测中心与 Bad Case：

| 选择器 | 失效声明 | 实际后果 |
| --- | --- | --- |
| `.table-action.is-danger` | `color: var(--danger)` | **危险操作按钮不是红色**，继承成普通色 |
| `.governance-table th` | `color: var(--text-muted)` | 表头该是弱化灰，实际是正文深色 |
| `.table-action` | `color: var(--accent)` | 操作按钮没有强调色 |
| `.status-muted` | `color: var(--text-muted)` | 「待核对」状态没有弱化 |
| `.governance-table th/td` | `border-bottom: 1px solid var(--border)` | 表格没有分隔线 |

这些地方**从未按设计意图渲染过**，迁移时必须显式决定，不能照抄当前像素。

## 2. Token

选值原则：**取现有最高频值**，让迁移的视觉位移最小。Tailwind v4 用 `@theme` 声明。

```css
@theme {
  /* 主色：取 --brand，它是 .primary-action 实际生效的值 */
  --color-brand:        #5744dd;
  --color-brand-hover:  #4532c7;   /* 原 --brand-dark */
  --color-brand-subtle: #f0edff;   /* 原 --brand-soft，用于选中底色 */

  /* 中性：全部来自现有最高频值 */
  --color-ink:       #171d31;   /* 正文，原 --ink */
  --color-ink-muted: #4f5873;   /* 次要文字 */
  --color-ink-faint: #8690aa;   /* 弱化文字，现有 14 处 */
  --color-line:      #e5e9f2;   /* 边框，现有 12 处 */
  --color-line-firm: #d8deeb;   /* 输入框等需要更实的边框 */
  --color-divider:   #edf0f5;   /* 表格行分隔，现有 17 处 */
  --color-surface:   #ffffff;
  --color-canvas:    #fafbfe;   /* 页面底色 */

  /* 语义色：只用于表意，不做装饰 */
  --color-danger:        #d94848;  /* 实体危险按钮背景 */
  --color-danger-text:   #c2354a;  /* 危险文字/边框，深一档保证对比度 */
  --color-danger-subtle: #fff0f0;
  --color-success:        #197d4a;  /* 取现有 .success-banner / .status-pill.is-success */
  --color-success-subtle: #eefaf3;
  --color-warning:        #ef8500;

  /* 圆角：15 种收敛为 4 档 */
  --radius-sm:   6px;    /* 标签、状态点 */
  --radius-md:   8px;    /* 按钮、输入框、卡片 —— 默认 */
  --radius-lg:   12px;   /* 弹层、面板 */
  --radius-full: 9999px; /* 胶囊标签 */

  /* 字阶：26 种收敛为 6 档，后台密集但可读 */
  --text-xs:   10px;  /* 辅助说明、表格内小字 */
  --text-sm:   11px;  /* 标签、次要信息 —— 现有最高频 */
  --text-base: 12px;  /* 正文、表格 */
  --text-md:   13px;  /* 按钮、输入框 */
  --text-lg:   15px;  /* 小节标题 */
  --text-xl:   20px;  /* 页面标题 */

  /* 阴影：14 种收敛为 3 档，且只用于浮层 */
  --shadow-pop:   0 4px 12px rgb(29 41 81 / 0.08);   /* 下拉、气泡 */
  --shadow-modal: 0 16px 40px rgb(29 41 81 / 0.10);  /* 弹层 */
  --shadow-focus: 0 0 0 3px rgb(87 68 221 / 0.18);   /* 焦点环 */
}
```

**间距不单独定 token**：Tailwind 自带 4px 基准刻度（`p-2`=8px、`p-3`=12px、`p-4`=16px），
恰好覆盖现有最高频的 8/10/12/16px。现有 136 种取值里的 7px、9px、13px、18px 一律就近
归档——这类一两像素的差异正是不一致的来源，不值得保留。

## 3. Button 的六个 variant

现有五套并行 class（`primary-action` 12 处、`secondary-action` 13、`danger-action` 4、
`table-danger-action` 3、`table-action` 1、`table-action is-danger` 1）**外加 47 个无
className 的裸 `<button>`**，全部归入下表。

| variant | 用途 | 外观 |
| --- | --- | --- |
| `primary` | 页面唯一主操作 | brand 底、白字、`radius-md` |
| `secondary` | 并列的次要操作 | 白底、`line-firm` 边框、`ink-muted` 字 |
| `outline` | 工具栏、筛选区 | 透明底、`line` 边框、`ink` 字 |
| `ghost` | 表格行内操作 | 无底无边、brand 字，hover 显浅底 |
| `destructive` | 删除等不可逆操作 | danger 底、白字（**确认弹层里**）；行内用 `ghost` + `danger-text` |
| `link` | 跳转 | 无底无边、brand 字、hover 下划线 |

尺寸三档：`sm` 高 28px（表格行内）、`md` 高 36px（默认）、`lg` 高 44px（表单提交，
对应现有 `.admin-page .primary-action`）；`icon` 为 32×32 正方。

硬性要求：

1. **一个操作区只能有一个 `primary`**。
2. **危险操作在表格里用 ghost+danger 文字，只有确认弹层里才用实体 destructive**——
   一行里出现红色实体按钮会把视线全吸走，而删除并不是这一行最重要的事。
3. **组件不暴露 `disabled`**：禁用只能通过 `blockedReason` 表达，「点不动又不解释
   自己」在类型层面就不存在。见 `CLAUDE.md` 第一条。
   例外：按钮文案本身已经说明原因时，用 `reasonHidden` 只留 `title`——「应用到 **0**
   份」里的那个 0 就是「还没勾选」，再补一句「请先勾选资料」只是重复，两个按钮各来
   一句还会把工具栏撑开。
4. Icon-only 按钮必须有 `aria-label`。
5. `loading` 期间禁止重复提交。

## 3.5 交互模式：删除 / 新建 / 列表

三条规则从第一个迁移文件（知识库详情的分类管理）里长出来，之后每个页面照此对齐。
它们是 CLAUDE.md 第一、二条在 UI 层的具体化。

### 删除

**一律走确认弹层，按钮永不因「有关联数据」而禁用。**

```
[删除]  →  ┌─ 删除分类 ─────────────────────┐
（红字     │ 「技术文档」下还有 1 份资料。   │
  ghost）  │ 删除分类不会删除资料，它们会    │
           │ 变成「无分类」，仍可被检索。    │
           │              [取消] [仍要删除]  │
           └─────────────────────────────────┘
```

- **不要在列表行里放禁用原因的占位小字**。6 行里 4 行带一句「请先迁移资料」，
  列表高度涨了三分之一，说的还是同一句话。后果说明放进弹层，那里装得下完整的话
  ——「删分类不删资料」这种关键信息，一行小字根本说不下。
- **行内用红字 ghost，实体红底只出现在确认弹层的主操作上**。一行里出现红色实体按钮
  会把视线全吸走，而删除并不是那一行最重要的事。
- **有关联数据不是拒绝删除的理由**，要说清后果让人自己决定。分类删除此前硬拦截
  （`CATEGORY_IN_USE`「请先批量迁移资料」）是伪分类时代的遗留：那时资料必须属于某个
  分类。取消伪分类后这条限制只剩下逼人先做一轮无意义的批量归类，已移除。
- 真正不可撤销的删除（资料、知识库）保持二次确认，文案要写明会连带删除什么。

### 新建

**与编辑复用同一个弹层，字段完全一致。**

- 不要用「列表上方一个输入框 + 按钮」的行内创建。它只能填一个字段，其余字段被写死，
  用户建完还得再点「编辑」补一遍——同一件事分两次做。
- 顺序类字段默认值取**现有最大值 + 100**，不要写死。写死会让每个新对象都和别人挤在
  同一档（原来所有新分类的排序都是 100，而模板分类是 100/200/…/600）。
- **必填校验用「点击后报错」，不要禁用提交按钮**（CLAUDE.md 第一条）。
- 首个输入框 `autoFocus`。

### 列表

统一结构，四段固定顺序：

```
页面标题 + 主操作（右上角，唯一的 primary）
    ↓
筛选 / 搜索
    ↓
表头 + 数据行
    ↓
分页
```

行内操作列：

- 高频操作直接展示，用 `ghost` + `sm`；危险操作用 `ghost` + `text-danger-text`。
- **一行里的操作不超过 4 个**，再多就收进「更多」。当前全站没有超过 4 个的，所以
  暂不引入 DropdownMenu（见第 5 节）。
- 操作列右对齐，主要信息左对齐。
- 空态给一句话说明「为什么空、下一步做什么」，不要只写「暂无数据」。

### 控件高度：同一横排必须同 size

`Button` / `Select` / `Input` 共用同一组高度档位——`sm` 28px、`md` 36px。共用不等于自动
对齐，**同一横排里的控件必须显式取同一个 `size`**，否则并排就是 28 对 36。

档位怎么选：

| 位置 | 档位 | 例子 |
| --- | --- | --- |
| 页面级工具栏（含右侧主操作） | `sm` | 知识库列表的搜索框 + 两个筛选 + 「知识库分类模板」 |
| 表格行内操作 | `sm` | 「编辑 / 停用 / 删除」 |
| 弹层表单 | `md` | 新建知识库、模板分类表单 |

工具栏的主操作也必须跟着降到 `sm`。曾经把它留在默认的 `md`，理由是「它是主操作，该更
显眼」——结果整排筛选控件比它矮一截。显眼靠的是 `variant="primary"` 的实底色，不是高度。

**文件选择器要用 `FileButton`，不要自己拼 `<label>` + 隐藏 input。** 原生 `<input
type="file">` 外观不可定制，于是全站都靠「藏起来 + 另给一个触发器」；触发器写成 `<label>`
就用不了 `<Button>`（`<button>` 里的 `<input>` 点不动），只能各自挂 class——工具栏那个
是 `.primary-action`（36px），表格行内那个是 `.table-file-action`（padding 3px、字号
11px），跟旁边 28px 的控件三方都不齐。`FileButton` 改用隐藏 input + `ref.click()`，触发
器就是真正的 `Button`，`size` / `variant` / `blockedReason` 全部继承。

### 弹层内的错误

**弹层打开时，错误必须显示在弹层内部。** Radix 会给背景内容加 `aria-hidden`，页面顶部
的错误横幅既在弹层背后、也不会被屏幕阅读器读到。实测过：在弹层里创建重名分类，
`409 分类名称已存在` 会显示在一个用户永远看不到的地方。

做法是页面级横幅加一个「有弹层打开时不显示」的条件，同一条错误只出现在用户此刻注视
的那个位置。

## 4. 迁移执行原则

1. **一次一个文件**，顺序按 className 密度：`KnowledgeBaseDetailPage`(45) →
   `ChatPage`(39) → `EvaluationCenterPage`(28) → `KnowledgeBasesPage`(24) → …
2. **按 class 清理，而不是按文件清理**。第一个文件迁完就发现「文件专属的 CSS」几乎
   不存在——`primary-action` 迁走 4 处后仍有 11 处在别的文件里用着。只有当某个 class
   的使用点降到 0 才能删它的规则（首个降到 0 的是 `.back-link`）。
   每次迁移后跑一遍使用点统计，把归零的删掉；否则 814 个选择器只增不减，
   迁移期的「两套体系并存」会变成永久状态。
3. 每个文件迁完跑一次视觉基线（`frontend/e2e/visual-baseline.spec.ts`），
   **逐张确认差异是有意的**，再 `--update-snapshots` 接受。
4. 第 1 节列出的 19 处失效声明，在迁移到对应文件时按本文档 token 显式补上，
   并在提交信息里说明「这里此前从未按设计渲染过」。

## 5. 不做的事

- **不引入 DropdownMenu**。全仓库当前零个自定义 dropdown（`div+onClick` 实测 0 处），
  没有要治理的对象。等真有「操作列需要收纳低频操作」的需求时再单独评估。
- **不重新设计视觉语言**。现有观感符合企业后台方向，本轮只做收敛。
- **不动业务逻辑、API、数据模型、路由语义**。

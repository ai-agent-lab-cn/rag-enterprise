# 评测治理缺陷闭环执行计划

> 目标：按 P0-1 → P0-2 → P0-3 → P1 连续完成 CI 基线、权限边界、验收证据真实性与 Bad Case 回归证据闭环。

## 1. P0-1：恢复 CI 基线

- 修复现有前端失败用例对应的产品行为：上传反馈、弹窗焦点恢复、报告请求契约。
- 清理当前 ESLint 阻断项。
- 修复 CI 中不可拉取的 MinIO 镜像与 release contract 缺失的 `SEARXNG_SECRET`。
- 运行前端测试、ESLint、生产构建和工作流契约检查。

## 2. P0-2：收紧权限与知识库证据范围

- 为工程指标和 Bad Case 列表增加可访问知识库集合过滤。
- 显式知识库参数先经过访问校验；未指定时仅汇总当前用户可访问范围。
- 链路验收仅从目标知识库当前活动索引版本读取检索与回答证据，禁止使用全局最新报告。
- 先补权限隔离与跨知识库拒绝测试，再实现查询约束。

## 3. P0-3：移除硬编码和伪证据

- Schema 版本读取 `schema_migrations` 当前值，不再固定为 14。
- Runtime 步骤绑定真实 Schema 与可追踪 Commit；无法证明时标记 blocked。
- ACL 与 Citation 指标必须来自同知识库、同活动索引版本的正式运行；缺失时 blocked，不再默认 0。
- 验收 API 不再接受调用方拼装的真假布尔量。

## 4. P1：完成 Bad Case 回归证据闭环

- 移除前端“点击即通过”的 `regression_passed: true`。
- 将 Bad Case 加入回归集与正式评测运行证据绑定：同知识库、正式、成功、通过，且运行明确覆盖该 Case。
- 保存 `last_evaluation_run_id`、真实通过结论与数据集版本；失败证据自动重开 Case。
- 补充后端迁移、状态流转测试、API 测试和前端交互测试。

## 完成门

- 后端相关测试与全量测试通过。
- 前端测试、ESLint、生产构建通过。
- 工作流配置与 release contract 校验通过。
- 真实页面完成桌面端与移动端检查；无法启动的外部依赖需明确记录为阻塞证据。
- 本轮只保留本地改动；等待用户再次明确“提交代码”后再 Commit/Push。

# 评测证据治理 P1-P3 实施计划

> 执行范围：在 P0 评测治理基础上完成证据绑定、证据有效性语义和跨工作区证据跳转；不新增数据库字段，不引入时间 TTL，不改变既有发布门禁。

## P1：证据绑定闭环

1. 先为证据链组装规则和索引版本详情加载行为补充失败测试。
2. 新增按知识库与索引版本严格限定的证据链查询，串联 `Index Version → Evaluation Run → Formal Report → Validation Report → Activation`。
3. 暴露只读 API、前端类型和请求方法，在索引版本详情中展示证据链。
4. 运行 P1 定向测试并创建独立提交。

## P2：证据有效性治理

1. 先为完整性、配置一致性、验证状态、发布状态和原因码补充失败测试。
2. 基于现有不可变事实派生证据语义；历史数据使用 `historical/unknown`，不以时间推断失效。
3. 在证据链中展示四类状态与可解释原因。
4. 运行 P2 定向测试并创建独立提交。

## P3：治理工作区关联

1. 先为正式报告、链路验收和 Bad Case 的证据入口补充失败测试。
2. 为索引版本、正式报告和验收步骤增加真实证据跳转；Bad Case 只展示已有来源事实，不把通用来源 ID 猜成报告 ID。
3. 保持评测中心、Bad Case、链路验收三个独立入口，统一证据语义和导航参数。
4. 运行相关前后端验证并创建独立提交。

## 合并验证

1. 复核三个提交均未包含用户已有的 `README.md` 与 `.superpowers/` 改动。
2. 完成评测治理相关测试、前端 Lint/构建以及桌面端/移动端真实页面检查。
3. 一次性推送到 `main`，检查唯一一轮 `main CI`，记录通过项与既有基线阻塞。

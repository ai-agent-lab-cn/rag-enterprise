# V5-8 生成治理与可信引用设计

## 目标

在现有五类回答状态和基础 `[来源 N]` 协议上，补齐 Citation 原文定位、生成前后治理、权限再校验与页面解释闭环。

## 设计

- `Source` 直接携带当前文档版本、内容哈希、标题路径、Sheet/行范围、外部资源 URL 等稳定定位字段。
- `GenerationGovernance` 记录证据数量、最低证据阈值、引用编号、引用有效性、声明覆盖结果与再校验结果。
- Prompt 生成前只接收当前查询已通过 ACL、有效期、检索状态和当前版本过滤的候选；PostgreSQL Citation API 再按相同 ACL 条件验证当前版本。
- 模型输出继续使用五种稳定状态；无效引用、无引用事实声明或冲突来源不足统一降级为 `generation_failed`。
- 页面点击 Citation 时读取受保护的定位 API，在弹窗展示原文片段和定位信息；失败不影响已返回的来源列表。

## 边界

- 不增加第二次 LLM 审核，不把模型自评作为治理结论。
- 不保存 Prompt、完整问题或供应商原始响应到治理日志。
- 不实现 PDF 坐标级高亮；本阶段定位到页码、标题路径、段落、Sheet 和行范围。
- 不修改 V5-9 Evaluation 指标体系，只输出其后续可消费的治理字段。

## 验收

- 无权、过期、删除或历史版本 Chunk 不能由 Citation API 读取。
- Citation 编号与来源一一对应，回答关键声明必须有合法引用。
- 证据不足、来源冲突、仅检索和生成失败均保持稳定状态并保留适用来源。
- 页面可展示治理结论并定位原文；历史记录兼容缺失的新字段。
